# Сравнение форматов сериализации: CBOR vs MessagePack

## Введение

Техническое задание (раздел 8) требует обоснованного выбора формата сериализации
из JSON, MessagePack, CBOR или Protocol Buffers. В данном документе сравниваются
два наиболее подходящих бинарных формата: **CBOR** и **MessagePack**.

## Критерии сравнения

| Критерий | CBOR (RFC 8949) | MessagePack |
|---|---|---|
| **Стандартизация** | IETF RFC 8949, формальная спецификация | Де-факто стандарт, спецификация автора |
| **Бинарные данные** | Нативный тип `bstr` (byte string) | Тип `bin` (добавлен в v2) |
| **Размер** | На 1–5% больше для малых сообщений | Минимально компактнее |
| **Расширяемость** | Тэги (tags) для семантической аннотации | Тип ext |
| **Самоописание** | Magic number `0xd9d9f7` (RFC 8949 §3.4.6) | Нет |
| **Детерминированность** | Определена (RFC 8949 §4.2) | Не гарантирована |
| **Канонический формат** | Стандартизован (RFC 8949 Core Deterministic) | Нет стандарта |
| **Целые числа** | Произвольная точность | До 64 бит |
| **Поддержка C++** | nlohmann/json, tinycbor, libcbor | nlohmann/json, msgpack-c |

## Выбор: CBOR

Выбран **CBOR (RFC 8949)** по следующим причинам:

1. **Формальная стандартизация** — наличие IETF RFC упрощает обоснование
   в записке и защите. Преподаватель может проверить соответствие RFC.

2. **Нативная поддержка бинарных данных** — тип `bstr` удобен для ключей,
   подписей, NodeID, зашифрованных payload. В MessagePack бинарный тип
   появился только во второй версии и не все библиотеки его поддерживают
   единообразно.

3. **Детерминированное кодирование** — RFC 8949 §4.2 определяет канонический
   порядок кодирования. Это критически важно для:
   - Подписи DHT-записей (подпись каноничного представления)
   - Транскрипта handshake (обе стороны должны вычислить одинаковый хеш)

4. **Тэги для семантической аннотации** — CBOR tag 0 (datetime), tag 2/3
   (bignum) и пользовательские тэги позволяют типизировать данные без
   потери компактности.

5. **Удобство реализации** — библиотека `nlohmann/json` поддерживает CBOR
   из коробки (`json::to_cbor()`, `json::from_cbor()`), что минимизирует
   зависимости.

## Компромиссы

- CBOR чуть больше по размеру (1–5%) из-за тэгов типов, но на наших
  размерах payload (≤64 КиБ) это незначимо.
- MessagePack более распространён в gamedev и IoT, но для криптографических
  протоколов каноническое кодирование важнее.
